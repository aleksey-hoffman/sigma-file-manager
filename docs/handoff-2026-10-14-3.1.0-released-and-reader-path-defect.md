## 四、本轮完成的事

### 4.1 三组修复（已发进 3.1.0）

1. **扩展代码校验器误判**（根因级）
   `sandbox.ts` 的 self 访问规则 `/(?<![\w$.])self\b/g` 直接扫原始源码，
   命中了扩展 `dist/index.js:191` 一句英文**注释**里的 `self-inflicted`，
   于是整份扩展在「创建 Worker 之前」被拒 → 路径同步看起来整体失效。
   修法：改词 + 新增 `strip-non-code.ts` 等长置空注释/字符串/模板串/正则，只扫可执行代码。

2. **侧车重试通道被自己废掉**
   `main.rs` 在 `match` 之外无条件 `wrote_back = true`，把**被拒绝**的写入也记成
   「已写过」；而 `should_resync_known_dialog` 以 `last_written_path(hwnd)` 去重，
   于是恒为 false，v0.5.7 的 G-1 重试通道被永久关闭。
   真机证据：`23:22:27 WriteFailed{extension_not_alive}` 之后 **52 秒零重试**。
   修法：抽出纯函数 `writer::write_succeeded(&WriteOutcome)`，只有成功路径登记 `current`。

3. **宿主侧可观测化**
   webview 的 console 不进应用日志（实测前端条目数为 0），诊断改写入
   `user-extensions.json` → `settings.customSettings.__hostWorkerDiagnostics`。

## 六、已坐实但未修的问题

### 6.1 `reader.rs` 读的是文件名框，不是目录 ★ 下一个该修的

`sidecar/src/reader.rs:38-59` 用 `FindAll(Descendants, TrueCondition)` 遍历对话框，
**取第一个 `UIA_EditControlTypeId`** 元素读 `ValuePattern`。深度优先遍历里，
第一个 Edit 是**文件名框**。

`main.rs:310` 把它当 `initial_path` 用于 `register_dialog` 与「是否回写」的判定，
注释写的是「Read the dialog's current path」——**与实际读到的内容不符**。

**真机日志铁证**（`%LOCALAPPDATA%\kizemo\focus-sync\logs\spike.log`）：

```json
{"event":"Read","hwnd":4588636,"app":"#32770","path":"Loop Engineering 快速留存.docx","strategy":"uia"}
{"event":"Read","hwnd":8852066,"app":"#32770","path":"dbeaver-ce-26.2.2-windows-x86_64.exe","strategy":"uia"}
{"event":"Read","hwnd":4588636,"app":"#32770","path":".learnings","strategy":"uia"}
```

返回的全是**文件名**，没有一个是目录路径。

**后果链**：`initial_path` 是文件名 → `register_dialog` 把文件名存成 `last_known_path`
→ 去重与 resync 比较的是「文件名 vs 目录路径」，**永远不相等**
→ 同一对话框反复写入 → 用户看到的闪动。

注意 `hwnd=4588636` 在 25 秒内触发了 3 次 Read，是重复写入的直接旁证。

**修的时候注意**：正确的读回目标不是文件名框。参见 `uia_inject.rs` 里
`compute_score_for_automation_id` 对 `41477` / `1001` 的处理——经典外壳对话框里
`Ctrl+L` 之后 `ComboBoxEx32 id=41477` → `Edit id=41477` 才是可写的地址 Edit；
`1001` 在 WinUI 3 另存为里是文件名框、**在经典外壳里是地址栏**，同名不同义，
不能按 aid 一刀切。

## 九、本轮踩到的坑（避免重蹈）

1. **PowerShell 把 markdown 反引号当转义符** —— 提交信息里的 `` ` `` 会吃掉下一个字符。
   提交信息一律写文件后用 `git commit -F`。
2. **PowerShell 5.1 的 `Set-Content -Encoding UTF8` 会写 BOM**。
   改 `version.json` 这类要被 `JSON.parse` 的文件会炸；用 Node 的 `writeFileSync(..., 'utf8')`。
3. **eslint 不读 `.gitignore`**。光给 `_acceptance/` 加 gitignore 不够，
   `eslint.config.ts` 的 `globalIgnores` 也要加。
4. **gitignore 无法在「父目录被排除」时救回子目录里的文件**。
   `_acceptance/**` + `!_acceptance/**/*.md` 会静默失效，
   必须中间插一条 `!_acceptance/**/` 把目录本身重新纳入。
5. **`prepare` 的中间态**：它先改 `package.json` 再构建，失败后版本号已升但包没出来。
   重跑前必须先把两处版本对齐，否则会二次升版本。
6. **删除跨盘文件会被安全策略拦**。同盘内改文件名让上传脚本的 `.exe` 过滤自然跳过，
   比移动/删除更省事（本次 3.0.3 就是这么处理的）。
