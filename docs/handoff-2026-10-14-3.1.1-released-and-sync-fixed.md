### 4.2 根因：两族对话框，日志里只记同一个 class ★

Edge/Chromium 有**两种结构完全不同的文件对话框**，而**两者对外都报 class `#32770`**，
唯一被记进日志的判别字段就是 class，所以它们被混为一谈长达数周：

| 族 | 文件名框 | `FileNameControlHost` | `is_winui3_wrapped` | H1 是否执行 | 路径跟随 |
|---|---|---|---|---|---|
| A Chromium 自绘（另存为 / 下载） | `1001`（Edit） | **有** | `true` | 执行 | 成功 |
| B 经典外壳（打开 / 浏览器上传） | `1148`（ComboBox+Edit） | **无** | `false` | **跳过** | 从不跟随 |

关键点：**`1001` 在 A 族是文件名框，在 B 族是地址栏**，同一个 automation id 语义相反。
`41477` 是 `Address Band Root`；B 族里 `Ctrl+L` 之后才出现可写的
`41477`（`ct=50004 class=Edit`）。

统计证据（`_acceptance/analyze-open-dialog.mjs`，对全部历史注入做交叉表）：
**27/27** 份带「保存(S)」默认按钮的 UIA 清单都带 `FileNameControlHost`；
带「打开(O)」按钮的 **3 份一份都没有**。

**所以 H1（`Ctrl+L` → 地址栏 SetValue → read-back → guarded Enter）这个机制从来没有坏过，
坏的只是它前面那道门。** 下载能用是因为它们落在 A 族；上传永远不能用是因为落在 B 族。

### 4.3 reader 修复（侧车 0.5.13）

`reader.rs` 原实现遍历对话框取**第一个 `ControlType == Edit`** 的元素读 `ValuePattern`，
深度优先遍历里那是**文件列表里的属性单元格**（`class=UIProperty aid=System.ItemNameDisplay`），
不是文件名框，更不是目录。

后果链：读回值是文件名 → `initial_path != current_path` 恒成立 →
`should_opened_write_back` 恒真 → 同一对话框反复写同一目标 → **用户看到的闪动**
（hwnd=722614：31 秒内 29 次写入同一目标 `E:\Models`）。

修法：读 `aid=1001` 的 **Name**（形状 `"地址: <path>"`），带形状校验
（`parse_address_label` / `looks_like_dir`，要求 `X:\` 或 UNC），
`41477` 作退路，取不到返回 `Err(NoDirectoryFound)`。
单次遍历同时收集两个候选，**不引入 `Win32_System_Variant` feature**（那会动依赖面，
且 `0x80040201` 的成本来自调用频率而非遍历宽度）。

真机验证（`verify-reader-live.ps1`）：同一对话框从 **205 次 Read / 270 秒**降到 **1 次**。

### 4.4 writer 修复（侧车 0.5.14）

1. **H1 不再受 `is_winui3_wrapped` 门控**，`uia_inject.rs:1271` 对所有对话框尝试。
   `is_winui3_wrapped` 降级为 debug 日志与 H2 分支的选择依据（`uia_inject.rs:1211`）。
2. **新增 DIRECT-1 护栏**（`uia_inject.rs:644`，常量 `FILENAME_BOX_AID` 在 `uia_inject.rs:531`）：

   理由：B 族上 `1148` 就是文件名框。若 `Ctrl+L` 未生效而焦点仍在文件名框，
   原逻辑会把整条路径写进去、read-back 还会**确认成功**、随后的 Enter 等于提交。
   **read-back 只证明「写进去了」，证明不了「写对了控件」** —— 护栏要挡的正是这个。
3. **订正两处错误根因注释**（见 §6.2）。

## 六、已坐实但未修的问题

### 6.1 reader 不认特殊文件夹的显示名 ★ 唯一功能性缺口

弹窗停在「文档 / 桌面 / 下载 / 图片」这类特殊文件夹时，地址栏显示的是**显示名**而非路径：

```text
aid="1001" ct=50021 class="ToolbarWindow32" name="地址: 文档" value=None
```

`looks_like_dir("文档")` 为假 → `reader.rs` 返回 `Err(NoDirectoryFound)` → `initial_path` 为空
→ `should_opened_write_back` 拒绝写入。

**影响面已被端到端实测钉死**：只影响**弹窗刚打开时的首次自动写回**。
`/set_path` 推送路径**不依赖 reader** —— 端到端那一次运行里
`read_failed err=no directory-shaped value in dialog` 与 `NAVIGATED=true` **同时出现**，
证明正常跟随不受影响。导航目标永远来自宿主推送的路径，reader 只参与「要不要写」的判断。

**本轮没修的理由**：0.5.13 的 reader 刚验证过闪动消除；放宽形状校验有把闪动放回来的风险。
真要修，需要把「显示名 → 真实目录」的解析做成**有界的**（六个 Known Folder 的固定映射），
而不是简单地把 `looks_like_dir` 放宽成「有分隔符就算」。

### 6.2 上一份 handoff 的结论已被推翻 ★ 必读

`docs/handoff-2026-10-14-3.1.0-released-and-reader-path-defect.md` §十写着：

> 注释说 `FileNameControlHost` 竞态，实测该节点在经典外壳对话框里根本不出现，
> `is_winui3_wrapped` 是结构性恒假。

**「结构性恒假」是错的。** 错在：只 dump 了一个实例就外推，
并且把「A 族有该节点」当成了矛盾证据而不是「存在两个族」。

同一句话的错误版本也曾写进 `uia_inject.rs` 的 v0.5.14 注释与 `http_server.rs` 的版本注释，
本轮已一并订正。**这三处现在是一致的正确表述，不要再改回去。**

推翻它的过程值得记住，因为方法本身可复用：
**两个观测互相矛盾时，不要挑一个信，要设计一个探针让「生产代码的判据函数本身」
在活对象上求值。** 本轮的做法是把 `has_filename_host && has_1001` 逐字复刻进探针，
在一个自建的真实「打开」弹窗上跑 —— 矛盾自己消解了（`has_filename_host=false`，
门控确实为假，但**原因不是「恒假」，而是「对 B 族恒假、对 A 族恒真」**）。

## 九、本轮踩到的坑（新增优先）

1. **探针可以自己骗自己**。`WM_SETTEXT` 往 ComboBox 写**返回 true 却什么也没做**，
   read-back 还确认「写成功了」。第一版机制探针因此报 `NAVIGATED=false`，
   而真实原因是**写错了控件**（`41477` 同时有 ComboBox 和 Edit，脚本挑中了前者）。
   → **凡是要证明「写对了控件」，必须先验控件身份（class + automation_id），不能只看返回值。**
2. **`SendInput` 发键前必须重新校验前台**。第一版探针的 Alt+D 泄漏到了用户的豆包窗口 ——
   因为发键前没校验。输入永远投递给**发键那一刻在前台的那个窗口**。
   → 这是生产代码 F-0 事故的同一个坑，探针也要守。
3. **探针只能操作自己创建的窗口**。更早一轮 `run-inject-probe.ps1` 枚举 `#32770` 取第一个，
   抓到了用户正在用的对话框并 `WM_CLOSE` 掉了，**用户的上传弹窗被关掉**。
   → 所有对话框探针必须先记录 pre-existing 窗口、只操作新建的、只关自己建的。
4. **探针的 JSON 要用 `serde_json` 生成**。手拼 `{"path":"C:\\Windows"}` 里 `\W`
   不是合法 JSON 转义，服务端返回 `invalid JSON body`，看起来**完全像产品失败**。
5. **`.NET` 的 `File.ReadAllLines` 打不开侧车正在写的日志**（独占打开失败）。
   用 Node（共享读）或先停侧车。
6. **PowerShell 5.1 `Get-Content` 把 UTF-8 当 ANSI**，会把 `办公文件` 读成乱码。
   读侧车/站点文件一律用 Node 或显式 `-Encoding UTF8`。
7. **JSON / package.json 一律用 Node `writeFileSync(..., 'utf8')`**；
   `Set-Content -Encoding UTF8` 会写 BOM，`JSON.parse` 会炸。
8. **提交信息一律写文件后 `git commit -F`** —— PowerShell 把 markdown 反引号当转义符。
9. **`gh release create` 不带 `--target` 时，tag 会指向远端默认分支 HEAD。**
   正确顺序：先把分支快进合入 `main` 并 `git push origin main` → `git tag v3.1.1` →
   `git push origin v3.1.1` → 再跑 `release:github`。顺序反了 tag 会落在没有新代码的提交上。
10. **`verify-changelog` 会在发版前拦截**。改了版本号就要补 `CHANGELOG.md` 条目，
    否则「更新弹窗会显示过期内容」直接 FAIL 整个发版。
11. 上一份 handoff 的坑仍然有效：`prepare` 的中间态、eslint 不读 `.gitignore`、
    gitignore 无法在父目录被排除时救回子目录、跨盘删除被拦。
    详见 `docs/handoff-2026-10-14-3.1.0-released-and-reader-path-defect.md` §九。

## 十、真机验收的硬约束（`AGENTS.md` 里已写，此处再强调）

- **真机验收必须用 `tauri build` 的打包产物，不能用 `tauri dev`**。
  dev 构建下所有路由页内容区空白，与代码无关，dev 上的界面结论一律作废。
- **代码注释里的「根因」不是 ground truth**，要独立证伪。
  本项目已经因此栽了两次，详见 §6.2。
- 拿不到 webview console 是常态（wry 不透传 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS`，CDP 连不上，
  `SendInput` 不可用）。可用手段：`PrintWindow(hwnd, hdc, 2)` 截图、UIA 树枚举、
  页面内 Vue DevTools 搜索框。**UIA 判别要带对照项，别只搜一个名字。**
- **取证工具链不得与被测链路不同源**。托管 UIA（PowerShell `UIAutomationClient`）与原生
  `IUIAutomation` 对同一元素的 `ControlType` 报告**不一致**，据此推导会引入真回归。
- **验收标准只能是「地址栏实际变化」**。
  `DialogOutcome::AddressBarWritten` / `Write strategy=uia` / `Injection succeeded`
  都只是「UIA 调用没抛异常」的映射，此前已在完全不移动的写入上误报过成功。
