## 1. 为什么做这一组

两件事，都来自上游仍然开放、且在本仓仍然成立的诉求。

**列表视图看不到缩略图。** 目前缩略图只在网格视图出现，且没有任何开关。列表视图每行只有一个 18px 的文件类型图标。用户在列表里翻找图片时无法凭画面辨认，只能逐个点开。上游 #231 的原话是「一个装满视频的目录里什么都没有显示」，本仓的网格视图已解决视频缩略图，但列表视图整体缺失。

**切列表/网格要点两次。** 工具栏右侧目前只有「文件夹树」「分屏」「信息面板」三个按钮，切换视图布局藏在 ⋮ 菜单的「导航视图布局」分组里。上游 #383 里用户抱怨「每次都得先开菜单，多花点击和时间」，维护者回复「保持开放，也许可以加个选项」。

## 2. 范围

三块改动，彼此独立，可分别验证。

| # | 改动 | 类型 |
|---|---|---|
| A | 列表视图显示图片/视频缩略图 | 新增组件 + 接入 |
| B | 工具栏新增列表/网格切换按钮，⋮ 菜单删除「导航视图布局」分组 | 修改 |
| C | 新增 `navigator.showListThumbnails` 设置项与 28→29 迁移 | 修改 |

### 明确排除

- **文件夹缩略图**：取文件夹内第一张图，需要新写后端逻辑，空文件夹无图可取。本轮不做。
- **文档（PDF/Word）缩略图**：需从文档渲染首页，依赖多、慢、失败率高。本轮不做。
- **抽出网格/列表共用的缩略图组件**：网格卡片里 variant 分流、双层淡入、尺寸计算、回退判定交织在一起，抽组件极易弄坏当前工作正常的网格视图。为消除一处重复而承担这个风险不划算（YAGNI）。
- **网格视图的缩略图开关**：本次开关只管列表视图，网格视图保持无条件显示。

## 5. 详细设计

### A. 列表缩略图组件

新增 `src/modules/navigator/components/file-browser/file-browser-list-entry-thumbnail.vue`。

**Props**：`entry: DirEntry`、`size?: number`（默认 32，指渲染尺寸）。

**判定**：直接复用 `isFileBrowserImageEntry` / `isFileBrowserVideoEntry`，不另写扩展名表。这样列表与网格的类型判定天然一致，不会出现「网格认成图片、列表不显示」。

**状态机只有两态**，刻意保持简单：

1. 既不是图片也不是视频 → 渲染 18px `FileBrowserEntryIcon`，**不建 IO、不发任何请求**
2. 是图片或视频 → 懒加载期间先显示原图标，缩略图就绪后原地替换为 32px

不做网格那套「浏览器端 20px 低清占位图 → 最终图」双层淡入。32px 尺寸下占位图的画质差别不可辨，却要多一轮 fetch 与两次 rAF 淡入，收益不抵成本。

**懒加载**：`onMounted` 建 `IntersectionObserver`，`rootMargin: '800px 0px'`、`threshold: 0`，与网格卡片一致。

**取缩略图**：
- 图片 → `ctx.getImageThumbnail(entry, size)`
- 视频 → `ctx.getVideoThumbnail(entry)`（无尺寸参数，固定 384×271）

注意两个接口的第二个参数语义是**缩略图生成的最大边长**，不是渲染尺寸。这里传 32 表示按 32px 上限生成，与显示尺寸一致；若传更小的值会导致缩略图被放大后模糊。本设计固定 `size = 32`，不提供调整项。

**回退**：缩略图拿不到（IO 未触发、生成失败、格式不支持）时保持原图标，不显示破图占位。

**生命周期**：`onBeforeUnmount` 断开 IO，并调用 `cancelImageThumbnail` / `cancelVideoThumbnail`。

#### 如何绕开 `v-memo`

缩略图 URL **只存在组件内部的 ref**，永不写回 `row` 数据、不进 `memoKey`。`v-memo` 拦的是父级 props 变化引起的整棵子树更新；子组件**自身**的响应式变化照常触发渲染。因此 `createDisplayRow` 与 `file-browser-list-view.vue` 的 memo 逻辑一行不改。

这一条是本设计中最容易被忽略、也最容易在实现时被破坏的约束。若后续有人「顺手」把缩略图 URL 提升到 row 上，缩略图将永远刷不出来，且不会报任何错。

### B. 列表视图接入

`file-browser-list-view.vue` 中 `FileBrowserEntryIcon`（当前 `:size="18"`）的位置，改为按设置与类型条件渲染新组件。设置关闭时行为与今天完全一致。

缩略图 32px 放进现有 42px 行内，上下各留 5px，`align-items: center` 居中。`LIST_ENTRY_HEIGHT = 42` 不改，虚拟布局一行不动。

### C. 设置项与迁移

- 新增字段 `navigator.showListThumbnails`，默认 `true`
- `USER_SETTINGS_SCHEMA_VERSION` 28 → **29**
- 迁移 28→29 使用 `setDefaultBooleanIfMissing(..., true)`

**为什么不是覆盖写**：Task 2 的框选用覆盖写，是因为该功能早已实现但默认关闭，用户不知道它存在，需要硬推一次。缩略图是**全新功能**，用户此前没有这个选项，不存在「此前的选择」被覆盖的问题。用「缺失才写」既满足「升级后直接能看到」，又保证用户日后主动关闭后不会被下次升级冲掉。

字段名沿用既有的 `showXxx` 风格（对照 `navigator.showHiddenFiles`），不用 `listShowThumbnails`。

- `settings.general.fileView` 分组新增第 5 项，排在「文件夹排在文件之前」之后
- i18n key：`settings.general.fileView.showListThumbnails` + `showListThumbnailsDescription`，沿用同组现有命名风格

### D. 工具栏布局切换按钮

- 复用该文件已 import 的 `ListIcon` / `LayoutGridIcon`
- 位置：现有「文件夹树」「分屏」「信息面板」按钮旁
- 行为：点击即切换到**另一个**视图（当前列表 → 点击后变网格；当前网格 → 点击后变列表）
- 图标语义：**显示当前所在视图**（在列表时显示列表图标）。与 Windows 资源管理器一致，用户无需记忆「这个图标点完会变成什么」
- 点击**必须复用 `setLayout()`**，不得写死全局。这样在 this-folder 作用域下点击时，改动的是当前文件夹
- 从 ⋮ 菜单删除「导航视图布局」整组（含其后的分隔符），其余 4 组（设置作用域 / 排序 / 显示 / 分屏模式）保持原样

**删除布局组后按文件夹设置布局的具体路径**：开 ⋮ 菜单 → 顶部「设置作用域」切到「仅此文件夹」→ 关闭菜单 → 点工具栏布局按钮。此时改动写入该文件夹的独立设置。原有能力未丢失，只是入口从「菜单内的布局按钮」变成了「作用域 Tab + 工具栏按钮」的组合。

## 6. 测试策略

项目的硬纪律：新测试必须先注入缺陷确认转红，且**失败输出须精确展示预期损坏**——只红不算数，等价变换的探针无效。

| 测试 | 判别性探针 | 期望的失败输出 |
|---|---|---|
| 非图片行不触发缩略图请求 | 让组件对所有行都建 IO | 「`.txt` 行调用次数为 0」失败，实际为 1 |
| 图片行进入视口后请求 | 把 `rootMargin` 改成 `0px`，测试中不滚动视口 | 「已请求」失败，显示未进入加载范围 |
| 生成失败回退原图标 | 让失败分支返回 `undefined` | 失败点必须落在「应渲染 FileBrowserEntryIcon」上，而非空泛 assert |
| 迁移 28→29 写入 `true` | 删掉迁移步 | `showListThumbnails === true` 失败，显示 `undefined` |
| 迁移不覆盖既有 `false` | 把 `setDefaultBooleanIfMissing` 换成覆盖写 | 失败信息显示 `false` 被改成 `true` |

后两条**必须成对**：只测第一条时，「总是写 true」与「缺失才写」都会通过，测试是平凡的。

此外需覆盖：`isFileBrowserImageEntry` / `isFileBrowserVideoEntry` 对列表视图的复用（至少断言 `.jpg`、`.mp4`、`.txt`、目录、无扩展名五种输入）。

## 8. 性能基准

本项目组的风险点就是渲染性能，基准不能省。

造一个 1000 张图片的目录，记录以下数字，并与网格视图做对照：

| 指标 | 说明 |
|---|---|
| 进目录到缩略图铺满的耗时 | 反映并发上限 3 下的排队速度 |
| 快速滚动时的帧率 | 反映虚拟滚动 + 每行一个 IO 的开销 |
| 列表/网格切换响应时间 | 反映组件挂载开销 |
| 常驻内存增量 | 图片缩略图是前端内存缓存，大目录下需确认增长可接受 |

数字写入验收记录。若内存或帧率不可接受，备选是把每行一个 IO 改为列表层共享单个 IO（IntersectionObserver 本身支持多 target），但**只有实测数据证明有问题时才做**。
