# AI 客户端能不能「自动发现」Alpha File Manager 的 MCP？

> 面向决策的调研结论，不是实施记录。日期：2026-10-16，对应版本 3.2.1-beta。

---

## 一句话结论

**不能自动发现。必须手动配置一次。**

这不是 Alpha File Manager 的缺陷，是 **MCP 这项协议本身就没有「发现」这个环节**。

MCP 协议只规定了「AI 怎么问服务器要工具」，**没有规定「AI 怎么找到服务器」**。业界所有 MCP 客户端——Claude Code、Minimax Code、OpenClaw、Cursor——**无一例外**都要你手动填一条地址。原因很简单：如果协议自带发现机制，任何一个恶意程序都能在你不注意的情况下偷偷冒充服务器被你的 AI 连上，协议作者不可能这么设计。

---

## 三个客户端分别怎么配

好消息是：**配置格式是通用的**，Alpha 生成的那一段 JSON，三个客户端都能直接用。

Alpha 在「设置 → 实验性功能 → MCP 服务」页面点「复制配置片段」，得到的就是：

```json
{
  "mcpServers": {
    "alpha-file-manager": {
      "url": "http://127.0.0.1:55100/mcp",
      "headers": { "Authorization": "Bearer <你的 token>" }
    }
  }
}
```

> 端口号和 token 每次启动都可能不同，要用页面上**当前显示的那一套**。

### Minimax Code

支持 `mcp` 工具的完整增删改查，本机实测 `mcp list` 返回 `{"servers": []}` —— 即当前未配置任何 server，功能可用。

最省事的做法：直接把上面那段 JSON 交给我（当前会话），我用 `mcp create` 帮你加进去，你连配置都不用碰。

### Claude Code

一条命令：

```
claude mcp add --transport http alpha-file http://127.0.0.1:55100/mcp --header "Authorization: Bearer <你的 token>"
```

- `--transport http`：本地 HTTP 服务，**不要**写 stdio。
- `--header`：把 token 带上。少了这个参数，所有请求都会被 401 拒绝。
- 默认写到用户级配置，对所有项目生效。
- 之后用 `claude mcp list` 查看、`claude mcp remove alpha-file` 删除。
- 验证过 Claude Code 的 `add-from-claude-desktop` 只对 Claude Desktop 格式有效，**不能**用来导入 HTTP 服务。

### OpenClaw

走自己的 `~/.openclaw/config.json`，同样是 `mcpServers` 结构（该文件在本机不存在，需要的话可新建）。OpenClaw 额外提供 mcporter 技能，可以用自然语言管 MCP，比如「列出所有已配置的 MCP 服务器」，省得手动改 JSON。

## 配置一次不够，还有第二道坎：端口会变

这是本项目特有的问题，也是「尽量少配置」这个诉求真正的难点。

| 场景 | 端口 | 后果 |
|---|---|---|
| 第一次开启服务 | 55100 | 正常 |
| 重启电脑后 | 55107 | **旧配置失效** |
| 55100–55199 被占满 | 55123 | **旧配置失效** |
| 重新生成 token | 端口不变 | **旧配置里的 token 失效** |

也就是说：**你昨天配好的，今天可能就连不上了**，而且失效时 AI 那边只会报一句「连不上」，不会告诉你原因。

Claude Code / Minimax Code / OpenClaw 都**不支持**在地址里写变量（比如 `${PORT}`），也不支持从文件间接读端口。协议层面没有这个能力。

### 三个可选方案

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. 固定端口**（推荐） | 服务永远用 55100，占用就换端口并提示 | 配一次，永久有效 | 极端情况下 55100 被别的程序抢占；换端口时仍需更新 |
| **B. 一键写入配置** | Alpha 生成配置文件，再调用各客户端的 CLI 自动追加条目 | 用户零操作 | 要写用户的客户端配置文件；token 变了仍要重写 |
| **C. 每次启动自动重写** | Alpha 启动时检测端口/token 是否变化，变了就更新各客户端配置 | 真正全自动 | **动用户其他软件的配置文件，风险和责任边界都很大** |

**我的建议是 A + 人工重配的组合**，理由是：

- A 解决了 90% 的场景（端口漂移），而 B、C 都解决不了 token 变化的问题。
- C 会修改用户**其他软件**的配置文件。这个行为一旦出错，用户很难排查是谁弄坏的。我不建议在没有你明确同意的情况下这么做。
- 如果你希望走 B 或 C，我可以实现，但需要你先明确授权写入哪些路径。

## 如果你想少配置，最实际的路径

按「省事程度」排序：

1. **让我帮你配 Minimax Code** —— 你把配置片段贴给我，我一条命令加进去，零手工。
2. **Claude Code 用一条命令** —— 复制粘贴改两个占位符即可。
3. **以后端口/token 变了** —— 回 Alpha 设置页重新复制一次，粘过去覆盖。

如果选方案 A（固定端口），第 3 步的发生频率会从「每次重启都可能」降到「几乎不发生」。

## 附：为什么不能「真自动发现」——安全上的硬道理

即便协议将来加了这个能力，Alpha 也不会实现它。原因：

- MCP 客户端会自动连接**同网段内所有声称自己是 MCP 服务器的东西**，这给了恶意程序一个极好的钓鱼位。
- 你的 token 只在你自己填进配置的那一刻才生效。自动发现等于**把 token 分发给网络上所有能应答的地址**。
- 本项目的 token 保护着「你电脑里有什么文件」这个信息，泄露的代价很高。

**手动配置 = 你的 AI 只连你亲手指定的那一个地址。** 这个摩擦是特性，不是缺陷。
